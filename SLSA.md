# SLSA (Supply-chain Levels for Software Artifacts)

## Target: SLSA Level 3

## What Level 3 actually requires
- Build happens on a hosted, ephemeral build platform (not a
  developer's laptop or a long-lived self-hosted runner an attacker
  could persist on).
- Provenance is generated by the build platform itself, not
  self-reported by the build script (this is the key difference from
  Level 1/2 — the attestation has to come from something the build
  process doesn't fully control, or a compromised build script could
  just lie about its own provenance).
- Provenance is signed and verifiable.

## Status: NOT IMPLEMENTED

`tools/security/signing/slsa-provenance.sh` documents why this can't
be a simple script: real SLSA 3 provenance for GitHub Actions requires
the official `slsa-framework/slsa-github-generator` reusable workflow,
run as a separate job with its own OIDC token, wired into the release
pipeline (not `security.yml`, which runs on every PR). That wiring
work is not done in this delivery.

## What IS implemented (adjacent, useful, but not SLSA provenance itself)
- Image signing via Cosign keyless signing
  (`tools/security/signing/cosign-sign.sh`,
  `cosign-verify.sh`) — proves the image was signed by CI's identity,
  which is a meaningful integrity control on its own, but is not the
  same as SLSA provenance (which also attests to *what inputs and
  build steps* produced the artifact).
- SBOM generation, which SLSA provenance often accompanies.

## Honest gate status
Quality gate G24 (SLSA Level 3) from the original M15 spec: **not met**.
